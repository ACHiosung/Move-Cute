# UI 구조와 갱신 방식 정리

## 추가 수정: 전투 종료와 보상 표시

아래의 최초 리팩터링 기록 이후 2026-10-31에 추가 수정했다.

- 턴 종료 효과·TurnEnd 반응을 모두 끝낸 뒤 전투 종료를 판단한다. 승리나 제한 턴 종료로 전투가 끝나면 실제 손패를 버리지 않는다. 계속되는 전투만 손패 버리기와 다음 턴 드로우를 실행한다. 기존 TurnEnd 구독자는 이제 버리기 전 손패를 관찰한다는 점을 전투 담당자와 공유해야 한다.
- 보상은 같은 씬의 기존 전투화면 위에 표시한다. 직전 손패 스냅샷과 복원 코드는 제거했다. 손패를 복제해 배경으로 만들지 않는다. 보존 기능을 추가 구현하지 않았다.
- `BattleConfig.rewards`가 골드·회복량·후보 풀을 소유하며 Context가 승리 시 한 번 생성한다. UI는 생성된 `BattleRewards`를 표시한다. 전용 BattleUIScreen 씬의 기존 10골드/회복2/네 기본 카드 후보 풀을 이 설정으로 옮겼다. 풀을 비우면 런 덱의 카드 종류를 사용한다.
- 카드 변경 알림은 표시 중인 상세/키워드 패널도 갱신한다. 브라우저 닫기와 포인터 비활성화는 호버 소유권을 반납한다.
- 뽑을 더미는 ID뿐 아니라 이동·키워드·비용·흑백 상태로 정렬한다. 관찰 가능한 변형본의 상대 순서가 원본 더미 순서에 좌우되지 않는다. 게임 RNG와 원본 더미는 변경하지 않는다.
- 배경 효과는 적용 전 렌더 색/알파와 CanvasGroup 입력 상태를 저장하고 정확히 복원한다. 버튼 전환 복원 시 자동 시작되는 색상 트윈도 정리한다.
- HUD는 값/언어/폭이 달라진 항목만 문자열과 막대를 갱신한다. Pointer의 매 프레임 Update를 제거하고 Hold가 지정된 버튼을 누르는 동안만 코루틴을 실행한다.

검증: 에디터 회귀 검사(종료 시 손패 유지, 연쇄 사기 회복 시 전투 계속, 제한 턴 종료, 표시기 없는 보상 생성, 배경 원상 복구) 통과. Play에서는 상세 키워드 갱신, 변형 카드 순서 독립성, 목록 닫기 호버 해제, 실제 손패 6장/동일 버튼 유지, 중복 보상 방지와 다음 전투 입력/밝기 복구, 에너지 길게 누르기를 확인했다. 이전 보류 네 오류와 Windows 빌드 환경 문제는 이번 수정에서 다루지 않았다.

## 최초 리팩터링 기록

2026-10-31. 이번 변경은 UI 내부와 새 BattleScreen 프리팹에 한정한다. 기존 전투·보상 규칙, 공용 씬, BattleManager, 카드/적/효과 데이터와 계약은 변경하지 않았다. 초기 덱 20장과 화면 배치도 유지한다.

## 책임 분리

| 구성 | 책임 |
|---|---|
| BattleScreenUI | 기존 IBattlePresenter / IPlayerInput 연결, 선택·호버 우선순위, 화면 전환, 모델 상태를 표시 값으로 변환 |
| BattleCardView | 일러스트·방향 아이콘·선택 테두리, 재사용 가능한 입력 라우팅. 게임 규칙을 계산하거나 상태를 변경하지 않음 |
| BattleEnemyView | 사기 바·예고·상태 표시. 텍스트와 수치가 바뀔 때만 해당 표시를 변경 |
| BattleTileView | 타일 색·텍스트·대상 테두리의 캐시된 참조 |
| BattleHandView | 손패 순서와 고정 비율 배치. 추가·제거·선택·영역 크기 변경 때만 배치 |
| BattleCardCollectionView | 덱/카드 더미 목록과 보상 후보에 사용하는 카드 슬롯 재사용 |
| BattleCellStripView | 에너지·남은 턴 칸 재사용. 값·개수·영역 크기 변경 때만 배치 |
| BattlePreviewView | 이동 화살표 재사용 |

partial 파일을 늘리는 것만으로 분리하지 않았다. 각 표시 컴포넌트가 자신의 참조·재사용 목록·표시 상태를 소유한다. 루트 조정자는 실제 게임 상태 변경을 기존 BattleContext 공개 함수에 위임한다.

## 갱신 원칙

- 입력 없는 프레임에는 손패/목록 재생성, 전체 UI 검색, 배경 재색칠을 하지 않는다. 조정자는 매니저가 제공하는 입력 가능 여부를 소수의 값으로 확인한다. 매니저에는 입력 상태 변경 이벤트가 없으므로 이 작은 확인은 남겨 두었다.
- HP·사기·장애물·상태 변화 알림은 해당 유닛/타일만 갱신한다. 타일 변화는 기존 TileEffectAdded/Removed 및 ObstaclePlaced/Destroyed 알림으로 처리한다.
- 선택/선택 해제/순간이동 목적지 모드에서는 테두리와 손패 선택 위치만 갱신한다.
- InputReady에서는 코어가 다시 계산한 카드 상태, 자원 수치, 현재 위치에 따른 적 예고를 동기화한다. 모든 타일을 다시 그리지 않는다.
- 전체 동기화는 전투 화면 생성, 전투 종료, 기존 언어 변경 콜백처럼 넓은 범위를 명시적으로 동기화할 때만 사용한다.
- 카드의 방향이 같으면 아이콘을 다시 배치하지 않는다. 적 예고 객체/언어가 같으면 설명을 다시 조합하지 않는다. IntentDeclared에서는 동일 객체를 재사용한 경우에도 명시적으로 설명을 무효화한다.
- Transform.Find/GetComponent는 초기 연결·새 뷰 등록 시에 사용한다. 카드·타일·적 표시에는 캐시된 참조를 사용한다.

## 재사용과 수명

- 손패 카드는 연출 완료 후 비활성 보관 영역으로 반환하고, 다음 뽑기에서 재사용한다. 반환 시 카드와 입력 콜백을 해제하며 재사용 시 크기/페이드 상태를 초기화한다.
- 카드 목록과 보상 후보는 각각 독립된 슬롯을 보유한다. 열 때마다 파괴/재생성하지 않고, 부족한 슬롯만 추가한다. 버튼 입력은 인스턴스당 한 번 등록하고 바인딩 대상만 교체한다.
- 재사용 용량은 현재 화면에서 필요했던 최대 개수다. 목록 20장을 다시 열거나 같은 이동을 반복 확인해도 오브젝트 개수가 늘어나지 않는다. 장기적으로 수백 장 이상의 목록이 필요해지면 프로파일링 후 가상 목록을 고려할 수 있다.
- 보상 배경은 CanvasRenderer의 RGB 배율로 어둡게 한다. 알파와 원래 Graphic 색을 유지하므로 HUD 텍스트가 다시 만들어져도 매 프레임 원본 색을 덮어쓸 필요가 없다. 종료 시 렌더 색과 버튼 전환 설정을 복원한다.
- 패널과 연결 사각형은 어둡게 하는 대상에서 제외한다.

## 에디터와 런타임

배치 생성은 BattleScreenUI.Authoring.cs, ViewAuthoring.cs 및 Browser.cs의 UNITY_EDITOR 구간에 있다. 플레이어용 컴파일에서는 제외된다. 실제 배치는 계속 프리팹에 저장한다.

기존 프리팹의 이미지·문구·위치를 지우고 재생성하지 않았다. `MoveCute > UI > Upgrade Cached Views`로 새 컴포넌트와 직렬화 참조만 연결할 수 있다. 신규 씬 생성 경로도 같은 표시 컴포넌트를 구성한다. 그림 교체는 기존 Image 또는 각 View의 직렬화된 참조를 사용한다.

## 검증

반복 실행 가능한 핵심 동작 검사는 에디터 메뉴 `MoveCute > UI > Validate Runtime Views`에 있다. 임시 오브젝트로 손패 변경 감지, 카드 슬롯 재사용, 휠의 관성 대체, 배경 틴트/복구를 검사하고 오브젝트를 제거한다. 공용 테스트 어셈블리나 패키지 설정은 추가하지 않았다.

에디터의 동일한 손패 6장 상태에서 비교했다. 아래 시간과 관리 힙 순증가는 에디터/리플렉션이 포함된 참고 수치이며 실제 플레이어의 FPS 보장이 아니다.

| 확인 | 결과 |
|---|---|
| 기존 손패 정렬 6,000회 | 약 30.36ms, 관리 힙 순증가 약 1.53MB |
| 변경 후 조정자 idle 확인 + 손패 dirty 확인 6,000회 | 약 3.51ms, 관리 힙 순증가 0, 실제 배치 0회 |
| 동일 카드 이동 미리보기 30회 | 화살표 용량 1 → 1 |
| 덱 20장 목록 닫기/다시 열기 | 슬롯 용량 20 → 20, 동일 오브젝트 재사용 |
| 턴 변경 전후 카드 뷰 수 | 27 → 27: 손패·대기 카드·덱 목록·템플릿 포함 |
| 보상 후보 닫기/다시 열기 | 슬롯 용량 3 → 3, 동일 오브젝트 재사용 |
| 보상 목록/후보 왕복 | 배경 틴트 적용 횟수 1 → 1 |
| 선택·카드 전환·상세 정보 복귀·선택 카드 상승 | 유지 |
| 순간이동·에너지 0의 전체 손패 흑백·턴 시작 회복 | 유지 |
| 카드 사용 후 즉시 승리·보상 10골드/회복 2/카드 1장 | 유지 |
| 다음 전투 진입 후 입력·밝기 복구 | 유지 |
| 신규 UI 배치 생성 경로 | 임시 오브젝트로 생성 검증 후 제거 |

기존 환경의 GetAllocatedBytesForCurrentThread는 제어 배열을 할당해도 0을 반환하므로, 정확한 할당량 측정으로 사용하지 않았다. 실제 빌드와 대상 기기 프로파일링은 이번 변경에서 실행하지 않았다.

## 의도적으로 보류한 항목

사용자 지시에 따라 이전 검사에서 재현한 다음 네 가지는 이번에 수정하지 않았다.

1. 손패 밖 CardChanged 알림의 KeyNotFoundException. 리팩터링 후에도 같은 예외를 확인했다.
2. 전투 종료 이벤트 완료 전 다음 전투 진입 가능성.
3. UI 제거 시 선택 대기 취소 누락.
4. 언어 변경 후 고정 문구 미갱신.

해당 항목과 향후 게임 진행·키워드·복합 효과의 규칙 변경은 별도 작업이다. 이번 구조 분리를 기능 완성 또는 해당 문제 해결로 간주하지 않는다.
